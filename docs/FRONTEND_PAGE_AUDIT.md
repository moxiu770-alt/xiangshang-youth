# 前端逐页可用性审计（2026-08-11）

本次审计以“用户能否进入、能否返回、能否完成操作、是否会误把 Mock 内容当成已提交数据”为标准。根工作台的底部 Tab 不应显示返回键；所有由卡片、列表、铃铛或“查看全部”进入的二级页面必须显示返回键。

## 已修复的 P0

| 范围 | 发现 | 本次处理 |
| --- | --- | --- |
| iOS 全部自定义标题页 | `ParentPageNavigation` 过去依赖各页手工传入 `showsBack`，遗漏时二级页没有返回入口。 | 改为以 `AppRouter.path` 为唯一依据：只要路由栈非空就显示返回；根工作台保持无返回。 |
| iOS 身体测评 | 原先是调用系统拍照/录像，再做单帧分析；不支持前后镜头、实时取景或语音。 | 改为全屏实时 Camera + Vision 关键点质量校验、前后摄像头切换、语音引导；原始帧不保存。 |
| Android 身体测评 | 原先启动系统相机 Intent，无法完成实时视觉引导。 | 接入 CameraX 预览和 ML Kit `STREAM_MODE`，支持前后镜头、运行时权限、实时质量提示及语音。 |
| 双端 BMI 首填 | 首次进入预置了身高、体重和父母身高，容易被误认为真实数据。 | 首填改为空；必须由家长实际选择数值后才能继续。BMI 公式独立于年龄，生日仅用于报告中的可选年龄别筛查。 |
| 双端实时姿态分析 | 质量门通过后仍存在关键点强制解包；异常帧或镜头切换可能触发崩溃。 | 关键点读取改为逐项失败闭合：缺失时提示重新取景并继续等待；跟练预览也不再强制解包。契约脚本锁定相机分析器不得出现 `!!`。 |

## 页面与入口审计

| 角色/区域 | 页面或入口 | 返回与操作结论 |
| --- | --- | --- |
| 登录/角色 | 启动、登录、注册、角色选择 | 根流程，不显示返回；角色选择后清空历史栈进入角色工作台。 |
| 家长 | 首页、我的测评、课程、班级圈、我的 | 五个底部 Tab 是根工作台，不显示返回；卡片进入报告、孩子管理、消息、身体测评、课程、专家后均走路由栈。 |
| 家长 | 孩子管理/绑定、报告、健康档案、消息、课程、专家、非体质测评 | 都是二级页，应显示返回。本次 iOS 已通过路由栈统一兜底；Android 由 `AppScaffold(onBack)` 或专用顶部栏处理。 |
| 家长 | 身体测评 | 顶部返回会在多步骤内先回上一步，首页步骤才退回来源页；避免误退出一半流程。采集取消后保留草稿。 |
| 教师 | 首页、班级圈、工作台、我的 | 根 Tab/工作台不显示返回；铃铛、班级看板、班级列表、学生、任务、任务详情、预警均为二级页。 |
| 教师 | 班级看板指标、风险学生、学生报告 | 指标和学生卡片均应可下钻。审计确认 iOS/Android 路由已配置；仍需真机逐项点测，见下方 P1。 |
| 教师 | 学生目录规模 | 远程总览首屏最多加载 100 名学生并保留 `studentTotal/studentPage/studentPageSize`；学生列表提供“加载更多”，不会把全校目录一次性塞进移动端内存。 |
| 家长 | 活动报名/专家预约 | 表单默认保持空白；仅在打开时带入当前账号的有效手机号，草稿、校验、提交中、失败重试和修改路径均保留，避免演示数据误提交。 |
| 学校管理 | 总览、年级、班级、风险 | 这些数据统一由后台数据看板提供，移动端不再承载校长工作台；移动端收到旧校长路由时只展示迁移提示，不显示旧 Tab。 |
| 学校管理 | 后台数据看板 | 后台继续提供学校总览、年级/班级对比、风险学生和任务下钻；移动端不复制这套权限和统计页面。 |

## 仍需在真机验收的 P1

1. **全尺寸点击回归**：iPhone SE/标准机/Pro Max、Android 小屏/刘海屏/平板的每一个卡片、铃铛和“查看全部”需要人工点测；当前源代码构建通过不等于真机导航已验收。
2. **实时视觉采集效果**：需在有 CameraX/Vision 支持的 Android 真机和 iPhone 真机验证前后镜头切换、权限拒绝后重试、暗光、逆光、全身未入镜、步态移动等情况。模拟器没有可靠实体摄像头，不能替代此验收。
3. **语音播报策略**：双端已增加统一的“语音动作引导”持久化开关，采集与跟练页的临时开关会同步到家长设置；提示仍使用系统 TTS，并在关键点提示上做节流。正式设备验收仍需覆盖耳机/系统静音、系统朗读（VoiceOver/TalkBack）并确认两者不抢焦点。
4. **医疗边界**：目前只做画面质量、关键点对齐提示和家长确认，未做脊柱侧弯诊断。上线前需由医学/合规负责人确认文案、知情同意、儿童影像处理说明和告警转介链路。
5. **数据真实性**：除明确隔离的 Mock 数据、草稿和离线队列外，统计、任务和报告在 Remote 模式均以服务端返回为准；家长运动打卡已接入按 `childId + checkInDate` 唯一约束的 `health-checkins` 接口、版本冲突、幂等提交、本地待同步队列和失败重试。视力、口腔和心理观察已使用稳定 questionId 及 single/multiple/frequency/severity/text 语义提交，不再把所有答案伪装成自由文本。联调后仍需用测试数据库验证真实迁移、跨设备冲突和学校时区边界。

6. **学校看板深链根路由**：风险通知进入学校后台看板时，iOS 已按角色根页重置导航栈，不再把看板压成带返回键的二级页；仍需在真实设备上验证从通知冷启动、热启动和系统返回行为。

7. **Android 跟练/体测语义**：四项拍摄入口、28 天训练日卡和动作选择卡已补齐 TalkBack 的按钮角色与当前/已完成状态文案；真实设备仍需检查焦点顺序、相机权限弹窗和 TTS 不抢焦点。

## 建议的下一轮前端验收顺序

1. 家长绑定孩子 → 身体信息录入 → 四项视觉采集 → 家长确认 → 结果/28 天计划 → 返回健康档案。
2. 教师首页 → 班级看板 → 风险学生 → 报告 → 连续返回至首页。
3. 后台数据看板 → 年级/班级/风险任一入口 → 报告 → 连续返回至总览；移动端校长旧链接应进入“学校管理看板已迁移至后台系统”提示页。
4. 逐项验证铃铛：有消息页的铃铛必须可点；无消息功能的装饰图标不得出现可点击样式。
