# 向上少年 Windows 场地体测端

这是面向 Windows 10/11 的场地端对接工程，而不是管理后台的网页替代品。它遵循边缘安全运行方式：下载任务、花名册、规则与标定配置后，网络中断时仍可查看本地名单、保护已经开始的采集事实和待同步记录；新的叫号、签到与正式采集必须恢复中央连接并重新通过开测检查。网络恢复后按事件唯一 ID 重放到中央服务。

## 工程边界

- `FieldClient.Core`：可测试的领域契约、中央服务 API、SQLite 本地出站队列和采集适配器接口。
- `FieldClient.Windows`：WPF 调度界面壳。实际深度相机、RGB 相机、显示屏、播报器和读卡器由实现 `ICaptureAdapter` 和 `IFieldHardwareHealthProvider` 的厂商适配包接入。
- 中央服务：`backend/` 的 `/v1/field/*`，设备使用 `X-Device-Id`、时间戳、单次随机数、请求体 SHA-256（`X-Device-Body-Hash`）和 HMAC 签名，不使用教师或管理员登录态，也不在每次业务请求传输设备密钥。签名串为 `METHOD + URL + timestamp + nonce + bodyHash`，GET/空请求体使用空字节摘要。

## Windows 部署前置条件

- 现场电脑使用 Windows 10/11 64 位。后台提供的自包含压缩包不需要安装 .NET SDK 或 Desktop Runtime，也不需要运行 `.ps1`；解压后直接双击 `FieldClient.Windows.exe`。
- 为每台边缘主机在后台注册测试点和设备。首次双击启动时，客户端会自动打开“连接场地端”向导；填写后台显示的服务器地址、设备 ID 和一次性设备密钥，点击“测试并保存”即可。连接通过后，密钥写入 Windows Credential Manager 的 `XiangshangField:DeviceCredentials` 通用凭证（用户名为设备 ID、密码为设备密钥），非敏感服务器地址单独保存。密钥轮换或连接中断后可直接点击主界面顶部“连接设置 / 恢复连接”，不需要在折叠区里寻找，也不需要 PowerShell。硬件厂商适配器可在右侧“设备、连接与同步”点击“采集设备与厂商 DLL”，选择 DLL、自动发现实现类型、测试并保存；普通现场人员无需再配置适配器环境变量。
- 使用本地 SQLite 文件保存任务快照、出站事件和证据上传进度；不要将学生资料写入临时目录或日志。
- 首次启动既可使用界面向导，也可由部署工具注入环境变量。客户端验证成功后会把不含密钥的服务地址保存到当前用户的本地配置；成对提供的设备 ID 和密钥会写入 Windows Credential Manager，随后从进程环境清除，之后可直接双击启动。生产环境会拒绝旧式 `X-Device-Key` 请求；本地密钥仅用于派生 HMAC 签名。仍应通过 MDM、客户端证书或硬件 TPM 进一步保护设备密钥。

## 构建与本地验收

工程固定使用 .NET 8。仓库根目录的 `global.json` 锁定 SDK 版本；若本机没有全局 SDK，可按以下方式使用工作区隔离 SDK：

```bash
export DOTNET_ROOT="$(pwd)/.tooling/dotnet"
"$DOTNET_ROOT/dotnet" test field-client/FieldClient.Core.Tests/FieldClient.Core.Tests.csproj --configuration Release
"$DOTNET_ROOT/dotnet" build field-client/FieldClient.Windows/FieldClient.Windows.csproj --configuration Release
```

发布维护人员可在 macOS/Linux 发布机生成后台下载包：

```bash
./field-client/package-windows.sh
```

脚本默认把自包含 ZIP 和发布清单写入 `backend/storage/releases`，后台会自动显示版本、大小、SHA-256 和下载按钮。该目录属于部署产物，不提交设备密钥，也不应预置学校信息。

也可在 Windows 发布机只生成单文件发布目录：

```powershell
pwsh ./field-client/publish-windows.ps1
```

默认输出到 `field-client/artifacts/field-client-win-x64`；发布物不能预置学校或设备密钥。普通现场安装可直接使用首次启动向导，批量部署则可继续由学校部署工具注入环境变量。

Windows 启动前由部署工具注入以下环境变量，不能将设备密钥提交到仓库：

```text
FIELD_API_BASE_URL=https://api.example.edu
FIELD_DEVICE_ID=<后台注册后返回的设备 ID，仅首次部署回退>
FIELD_DEVICE_KEY=<仅显示一次的设备密钥，仅首次部署回退>
FIELD_LOCAL_DB=C:\ProgramData\XiangshangField\field-client.db
FIELD_CAPTURE_ADAPTER_ASSEMBLY=C:\Program Files\XiangshangField\VendorAdapter.dll
FIELD_CAPTURE_ADAPTER_TYPE=Vendor.Adapter.CertifiedCaptureAdapter
```

普通现场安装不需要执行上述命令：安装后直接双击 `FieldClient.Windows.exe`，按首次启动向导填写后台给出的三项接入信息即可。Windows 电脑与服务器不是同一台机器时，服务器地址必须使用 Windows 能访问的局域网 IP 或正式域名，不能填写 `localhost`。上面的 `FIELD_CAPTURE_ADAPTER_*` 仅保留给自动化部署；人工部署应把厂商整个依赖目录复制到安装包的“采集适配器”目录，再展开主界面右侧“设备、连接与同步”，点击“采集设备与厂商 DLL”完成识别和保存。

应用启动后会发送设备心跳、下载全部可用任务目录、当前任务和队列；现场人员可在顶部切换已发布任务，所选任务会保存到本机，重启后继续使用，服务端归档该任务时自动回退到当前可用任务。运行期间每 15 秒自动续报心跳、刷新任务与队列、处理后台下发的暂停/恢复/叫号等指令，并尝试补传本地事件。后台下发的暂停或停止会持久保存在本机，Windows 重启后仍保持锁定，直到收到明确的恢复指令。最近一次成功下载的任务与名单会保存为 SQLite 快照，断网重启时仍可查看名单和本地记录；由于无法确认实时队列、设备与标定状态，离线模式不会放开新的叫号、签到或正式采集。已经开始的采集事实与证据会先安全保存到本机，待网络恢复后同步。叫号及开始采集先落入 SQLite，再由自动同步或“立即同步”按批次幂等上传。正式采集中，主工作区会把厂商适配器的动作事实转换为当前项目、设备提示、动作进度、置信度、事件数量与最近反馈时间；只读取白名单进度字段，不把任意诊断载荷暴露给现场人员。开始采集前还会保存稳定的活动会话意图；如果 Windows 或采集进程异常退出，重启后会明确显示“处理中断采集”，把旧会话关闭并原子安排补测，不会让学生永久卡在“测试中”。完成采集时，客户端先按中央规则校验项目、分值、置信度和本地证据，向操作员展示逐项成绩和低置信度提示，经人工确认后才进入出站队列；结果异常时可直接“终止并安排补测”，不会卡在已经停止却无法结束的采集状态。确认提交后，证据会复制到 `%LocalAppData%\XiangshangField\evidence` 并持久记录上传进度；只有证据上传成功后才组装 `session.complete`，中央端确认整个完成事件后才删除受管副本。`session.open`、动作事件、`session.complete` 与 `session.abort` 都使用客户端稳定 ID，因此可在同一断网批次中顺序补传，不依赖中央端预先返回的会话 ID。

客户端心跳会从当前可执行程序集读取真实三段式版本号，不再使用源码中的固定版本。后台设备卡片会把上报版本与当前安装包比较，集中显示待升级设备并提供“下载新版”入口；更新完成且客户端重新连接后，版本状态会自动变为“已是最新版”。

后台下发的暂停、停止或恢复还会写入中央设备控制状态；Windows 重启、命令回执丢失或本地状态重建后，场地端仍以中央状态为准保持锁定或恢复。场地人员签到前必须核对姓名、班级、学籍号、性别和出生日期；顶部“紧急停止”会立即锁定新操作、停止活动采集、将中断会话转入补测，并把急停状态随心跳上报中央。急停状态保存在本机，重启后不会自行解除。

测试点自身的“暂停”“维护”“停用”同样属于中央持久状态，设备心跳不会把这些状态自动覆盖成在线。Windows 端会分别说明暂停、维护、停用或等待重连，并锁定新的叫号、签到与采集。恢复时后台先将测试点改为离线等待连接，随后由边缘主机的真实心跳恢复在线，避免人工伪造在线状态。

现场工作台会持续显示下一位候测学生和待叫号、处理中、已提交、异常四类数量；完成、缺席或补测处理后自动移出当前筛选并选中下一位。常用快捷键为 `F2` 叫号、`F3` 签到、`F4` 开始采集、`F5` 刷新名单、`F8` 核对并提交成绩；输入搜索内容时快捷键不会误触业务操作。

开测状态使用中央服务下发的结构化检查清单，不再只显示一条笼统错误。Windows 端优先列出最多六项阻断与具体处理方法；后台每台设备的“开测检查”可展开查看中央控制、测试点连接、认证适配器、双深度相机、RGB 相机、GPU、帧同步、本地存储、标定一致性与紧急停止的完整结果。清单只改善排障说明，不会放宽正式采集门禁。

Windows 场地端每 15 秒自动刷新中央任务与本站候测名单，并在队列标题下显示最近同步时间。后台新增、移出、换点或调整学生状态后，场地端会明确提示新增、移出和更新人数及学生姓名，避免操作员继续使用旧名单；正式采集中不会用普通名单提示覆盖当前采集或中断恢复提示。后台“场地中控”的测试点卡片同步显示当前任务的实际占用、待叫号、处理中人数和容量进度。

后台安全关闭当前任务时，仍在采集或待复核的会话会先阻止关闭。关闭成功后，客户端清除旧任务选择并停止叫号；如果中央端还有另一项已发布任务，则自动切换并要求操作员重新核对名单，否则明确显示“现场任务已关闭”。

主界面顶部会同时显示当前任务的项目范围和本站测试能力。“整套任务通道”完成任务中的全部项目；“单项通道”只允许项目完全相同的单项任务。测试点与任务不匹配时，场地端保留名单查看和同步能力，但锁定正式采集；认证适配器返回的成绩若缺少任务项目或包含任务外项目，也不会进入离线待同步队列。

推荐由 MDM 或部署脚本写入 Windows Credential Manager：

```powershell
cmdkey /generic:XiangshangField:DeviceCredentials /user:<FIELD_DEVICE_ID> /pass:<FIELD_DEVICE_KEY>
```

写入后删除部署期 `FIELD_DEVICE_ID`、`FIELD_DEVICE_KEY`，并避免将其写入注册表、安装包、日志或排障截图。

发布包本身不包含任何硬件厂商 DLL。未安装经认证的相机/计时器适配器时，客户端会如实上报 `manual-fallback` 与未通过的 `field-health/v1` 自检；中央端会锁定正式开测，不会把人工兜底误报成视觉评分。接入硬件后，厂商适配器必须提供真实自检、标定复核、采集事件与设备生成的成绩；仅通过中控门禁后才可生成正式会话。人工异常处理应在后台复核/补测流程中完成，不得绕过中央复核规则；服务端也会拒绝带 `manual-fallback` 标识的正式会话。

## 离线一致性契约

1. 每项边缘事实生成 UUID `clientEventId`；同一事件任意次数重传只生效一次。
2. 同一批事件有持久化的 `clientBatchId`；网络断开于中央端提交完成之后，重试仍使用原批次 ID，直接取得中央端缓存回执。
3. 中央端会校验重放的 `clientEventId`、事件类型与内容摘要完全一致；同一 ID 的不同内容会被拒绝并保留为客户端“冲突”，不自动覆盖中央记录。
4. 队列状态携带 `expectedVersion`；版本冲突时停止覆盖，重新下载花名册/队列后由教师或管理员处理。
5. 服务端处理中的批次最多保留五分钟租约；边缘主机或网络异常中断后可由同一设备用原批次 ID安全接管重放。
6. 证据先复制到客户端受管目录并记录 SHA-256，再通过 `/v1/field/files/*` 上传；上传成功后才将文件 ID 写入会话完成事件，中央端确认后再清理本地受管副本。
7. 成绩最终由中央端基于规则版本、标定版本、算法版本和置信度确认；低置信度自动进入复核。
8. 采集进程异常退出后不得伪造完成结果；客户端重启时重放稳定的 `session.open`，再提交 `session.abort`，中央端同步关闭会话并将学生转为待补测。

> 本工程不虚构硬件算法实现。接入具体相机/计时器后，需要对每个设备型号做标定、准确度、断网、断电恢复和人工复核验收。
