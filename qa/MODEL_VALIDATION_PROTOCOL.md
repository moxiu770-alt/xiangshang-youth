# 身体采集与跟练算法验证协议

状态：`pending-human-validation`。本文件定义发布门槛，不代表当前算法已经达标。

## 1. 姿态采集动作标准

前屈观察（Adams）必须保持：双脚并拢、双膝完全伸直、双手合拢自然下垂，缓慢前屈到躯干接近水平；观察方向为儿童背后。屈膝、弓步、单脚前后站立或身体未完整入镜均判为无效采集，不能生成姿态结论。

手机 RGB 二维画面只记录可见关键点、动作完成度、采集质量和候选几何量。不得把相机代理量命名为 ATR、Cobb 角、肋峰或医学诊断；ATR 需要 Bunnell 脊柱测量仪或经过审批的等效校准设备。

每个手机采集项目须完成两次独立记录：完成第 1 次后离开人型框，再重新入镜完成第 2 次。两次可比较指标的最大差异需满足厘米量 ≤0.8 cm、角度量 ≤3°；否则保留最新记录作为新的第 1 次并要求重拍。`UY-CAPTURE-GUIDED-2.x` 只有写入 `two-take-repeatability` 质量门后才能提交。该门仅证明引导采集稳定，不等同于物理标定。

家庭端商业筛查不要求用户准备标定板。它依靠固定后置 1×、人体框、设备水平、完整入镜、两次独立采集和真实儿童人工标注验证，输出“是否需要重采/专业复核/继续观察”的筛查行动；摄像头投影量不得显示成物理厘米、ATR、Cobb 角或医学诊断。

只有需要高精度物理几何测量时才另需：后置 1×固定机位、脚位地垫、可检测的 L 形标定板、每机型镜头内参，以及 PnP 重投影误差 ≤2 px。每一个“手机型号 + 后置 1×镜头 + 分辨率”还必须在服务端的 `MOBILE_CAPTURE_CALIBRATION_PROFILES_JSON` 中有激活的 `profileId`；其 `boardId`、`intrinsicsId`、`lensId`、`resolution` 必须和本次采集完全一致，并保存实测 3×3 内参矩阵、畸变系数、标定板物理宽高、marker 尺寸和版式 SHA-256。配置模板见 `backend/config/mobile-capture-calibration-profiles.example.json`。当前 App 的家庭流程属于“引导式筛查采集”，不具备物理测量资格，但这不妨碍其在完成独立人工验证后作为筛查和分流工具使用。

## 2. 同一儿童十次重复性门禁

每名儿童、每个动作至少连续独立采集 10 次。十次期间必须冻结：App 版本、算法版本、阈值版本、设备型号、镜头方向、机位、距离、光线与动作口令。每次开始前重新站位，不允许从同一视频重复抽帧冒充独立测量。

工程门槛：

- 有效采集成功率至少 90%。
- 姿态厘米代理量十次极差不超过 0.8 cm。
- 姿态角度代理量十次极差不超过 3°。
- 跟练计数平均绝对误差不超过 0.5 次。
- 跟练计数完全一致率至少 90%，单次最大误差不超过 2 次。
- 发布级重复性数据至少覆盖 20 名独立儿童和 2 种设备。

执行：

```bash
node scripts/evaluate_capture_repeatability.mjs \
  --input /secure/repeatability-corpus.json \
  --release-gate \
  --output /secure/repeatability-report.json
```

重复性达标只说明输出稳定，不说明健康结论正确。

## 3. 人工标注与一致性门禁

- 独立验证集不得参与阈值调参或训练。
- 至少 10% 样本由两名筛查人员独立盲复测。
- 双人一致性 Cohen's Kappa 必须不低于 0.80。
- 研发并发布按年龄变化的候选阈值前，6–18 岁每个周岁年龄至少 500 例独立样本。
- 样本必须记录匿名组 ID、不可逆文件摘要、年龄、性别、设备、镜头、光线、标注协议版本和冻结算法版本。
- 儿童监护人同意、伦理/隐私审查、数据脱敏与保留期限必须在采集前完成。

生产 App 的“不保存原始视频/照片”承诺不因模型验证而改变。若验证研究确需专业人员查看影像，必须使用单独监护人同意、单独访问控制和单独保留策略的验证环境；生产 API 只接收结构化结果。可先生成不含身份、路径和模型输出的盲审工作单：

```bash
export VALIDATION_PSEUDONYM_KEY="$(openssl rand -hex 32)"
node scripts/prepare_blinded_validation_export.mjs \
  --input /secure/model-validation/source-manifest.json \
  --output /secure/model-validation/blinded-worklist.json
```

密钥只能存放在密钥管理服务，不得写入 Git。脚本会使用 HMAC 生成不可逆样本码，隐藏模型输出，并确定性抽取至少 10% 样本进行双人独立盲审。

## 4. 发布规则

只有同时满足以下条件，模型注册表才允许从 `pending-human-validation` 改为 `human-validated`：

1. 独立人工标注集通过离线准确率门禁。
2. 同人十次重复性数据通过发布门禁。
3. 10% 双人盲复测和 Kappa 门禁通过。
4. 数据、报告 SHA-256 与审批记录一致。
5. 算法负责人和安全/专业复核人完成独立签核。
6. 八个姿态问题域各自完成不少于 500 例的独立盲测，且每个域的敏感度、特异度、阴性预测值、重复性 ICC 和不可判定率都达到预注册门槛。

任一条件缺失时，App 只能显示采集记录、质量提示和家长确认的辅助计数，不得显示姿态风险等级、准确率、相机已验证或医学结论。

家庭引导式筛查与专业物理测量分别审批：前者审批的是行动分流分类准确性，后者还必须额外审批标定板、镜头内参、PnP 重投影误差和物理量误差。不得用前者的审批替代后者。
